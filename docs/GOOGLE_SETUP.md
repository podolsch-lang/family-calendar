# Google 캘린더 연결 방법

이 문서는 개발을 하지 않는 사람을 위한 순서입니다. 한 번만 해 두면, 아빠 휴대폰과 엄마 휴대폰이 **가족 공유 캘린더** 하나를 같이 보고 고칠 수 있습니다.

앱 주소는 `https://podolsch-lang.github.io/family-calendar/` 입니다.

연결하기 전에도 앱은 다 쓸 수 있습니다. 그때는 일정과 근무표가 **그 휴대폰 안에만** 남습니다. 아래를 끝내면 두 사람이 같은 내용을 봅니다.

클라이언트 ID는 비밀번호가 아닙니다. 저장소에 적어도 됩니다. **클라이언트 보안 비밀번호(client secret)는 만들지 말고, 만들어져도 어디에도 붙여 넣지 마세요.**

## 준비물

- 아빠 Gmail, 엄마 Gmail
- 컴퓨터 브라우저 (휴대폰보다 화면이 넓어 편합니다)
- 이 저장소를 수정할 수 있는 GitHub 로그인

## 1. Google Cloud 프로젝트 만들기

1. 컴퓨터에서 [https://console.cloud.google.com/](https://console.cloud.google.com/) 를 엽니다.
2. 아빠 Google 계정으로 로그인합니다.
3. 위쪽 프로젝트 이름(또는 ‘프로젝트 선택’)을 누릅니다.
4. **새 프로젝트**를 누릅니다.
5. 프로젝트 이름을 `가족캘린더`처럼 알아보기 쉽게 적고 **만들기**를 누릅니다.
6. 알림이 뜨면 그 프로젝트가 선택됐는지 위쪽에서 한 번 더 확인합니다.

## 2. Google Calendar API 켜기

1. 왼쪽 메뉴 ≡ → **API 및 서비스** → **라이브러리**.
   주소로 바로 가도 됩니다: [https://console.cloud.google.com/apis/library](https://console.cloud.google.com/apis/library)
2. 검색창에 `Google Calendar API`를 입력합니다.
3. **Google Calendar API**를 누르고 **사용**(또는 사용 설정)을 누릅니다.
4. ‘API 사용 설정됨’이 보이면 됩니다.

## 3. 동의 화면 (테스트 모드)

가족 두 명만 쓸 것이므로 **테스트** 상태로 둡니다. 구글 심사(프로덕션 게시)는 하지 않아도 됩니다.

1. **API 및 서비스** → **OAuth 동의 화면**.
2. 사용자 유형이 보이면 **외부**를 고르고 만듭니다. 이미 만들어져 있으면 다음으로 갑니다.
3. 앱 이름은 `우리 가족 캘린더`, 사용자 지원 이메일은 아빠 Gmail, 개발자 연락처도 아빠 Gmail로 적습니다.
4. 저장하고 계속합니다.
5. 범위(scope) 단계가 있으면 일단 저장하고 계속해도 됩니다. 앱이 나중에 캘린더 권한을 요청합니다.
6. **테스트 사용자**에 **아빠 Gmail**과 **엄마 Gmail**을 둘 다 추가합니다. 여기에 없는 계정은 로그인할 수 없습니다.
7. 게시 상태는 **테스트**로 둡니다.

테스트 모드에서는 가끔(대략 일주일 정도 지나면) 다시 로그인해야 할 수 있습니다. 동기화 버튼을 누르고 Google 화면이 나오면 다시 허용하면 됩니다.

## 4. 웹 클라이언트 ID 만들기

1. **API 및 서비스** → **사용자 인증 정보**.
2. 위 **+ 사용자 인증 정보 만들기** → **OAuth 클라이언트 ID**.
3. 애플리케이션 유형은 **웹 애플리케이션**.
4. 이름은 `가족캘린더 웹` 정도면 됩니다.
5. **승인된 자바스크립트 원본**에 아래를 그대로 추가합니다. 뒤에 경로를 붙이지 않습니다.

   `https://podolsch-lang.github.io`

   틀린 예: `https://podolsch-lang.github.io/family-calendar` (경로가 들어가면 안 됩니다.)
   틀린 예: 마지막에 `/`가 있어도 보통은 되지만, 위 한 줄과 똑같이 두는 것이 안전합니다.

6. **승인된 리디렉션 URI**는 비워 둡니다. 입력란이 필수라고 나오면 원본과 같은 `https://podolsch-lang.github.io` 를 넣습니다.
7. **만들기**를 누릅니다.
8. 화면에 **클라이언트 ID**가 나옵니다. `숫자-영어.apps.googleusercontent.com` 형태입니다. 복사해 메모장에 잠깐 둡니다.
9. **클라이언트 보안 비밀번호**가 같이 보이면 무시합니다. 복사하지 마세요.

## 5. 클라이언트 ID를 앱에 넣기

1. GitHub에서 이 저장소를 엽니다.
2. `config.js` 파일을 클릭합니다.
3. 연필 아이콘(Edit)을 누릅니다.
4. 아래처럼 따옴표 **안**에 복사한 ID만 붙여 넣습니다.

```javascript
window.APP_CONFIG = {
  GOOGLE_CLIENT_ID: "여기에-붙여넣기.apps.googleusercontent.com",
};
```

5. 다른 글은 지우거나 고치지 않습니다.
6. 오른쪽 위 **Commit changes**로 `main` 브랜치에 저장합니다.
7. **Actions**에서 배포가 끝날 때까지 1–2분 기다립니다.
8. 휴대폰에서 앱 주소를 새로고침합니다. 위 배너의 문구가 바뀌거나, 설정에 **Google로 연결** 버튼이 보이면 성공입니다.
9. 예전 화면이 남으면 브라우저에서 새로고침을 한 번 더 하거나, 홈 화면 앱을 완전히 닫았다가 다시 엽니다.

## 6. 가족 공유 캘린더 만들기

아빠 휴대폰(또는 컴퓨터의 Chrome)에서 합니다.

1. 앱 → **설정**.
2. **Google로 연결**을 누릅니다.
3. 구글이 ‘확인되지 않은 앱’이라고 경고하면, 가족만 쓰는 앱이라 정상입니다.
   - **고급** (또는 Advanced)을 누릅니다.
   - **우리 가족 캘린더(으)로 이동**을 누릅니다.
   - 캘린더 권한을 **허용**합니다.
4. 아빠 Gmail이 맞는지 확인합니다. 다른 계정이면 그 계정도 3단계의 테스트 사용자에 있어야 합니다.
5. **가족 공유 캘린더 만들기**를 누릅니다.
6. ‘선택됨: 가족 공유 캘린더’가 보이면 그 캘린더가 연결된 것입니다.
7. **엄마 Gmail 초대**에 엄마 메일 주소를 적고 **수정 권한으로 초대**를 누릅니다.
8. 엄마는 메일(또는 휴대폰 Google 캘린더 앱)에서 초대를 수락합니다. 권한은 보기만이 아니라 **일정 변경**이어야 둘 다 일정을 넣을 수 있습니다.

초대가 가지 않으면 컴퓨터에서 [https://calendar.google.com](https://calendar.google.com) 을 엽니다.

1. 왼쪽 내 캘린더에서 **가족 공유 캘린더** 옆 ⋮ → **설정 및 공유**.
2. **특정 사용자와 공유** → 엄마 Gmail → 권한 **일정 변경 및 공유 관리** 또는 **일정 변경**.
3. 보내기를 누릅니다.

기본 캘린더(내 개인 일정)를 고르면 개인 약속과 가족 일정이 섞입니다. 가족 공유 캘린더를 따로 쓰는 것이 좋습니다.

## 7. 엄마 휴대폰

1. 엄마도 같은 주소로 앱을 열고, 홈 화면에 추가합니다.
2. 설정 → **Google로 연결**. 엄마 Gmail로 로그인합니다. 역시 ‘확인되지 않은 앱’ 경고가 나오면 고급 → 이동 → 허용입니다.
3. **캘린더 목록**을 누르고 목록에서 **가족 공유 캘린더**를 고릅니다. 아빠가 만든 것과 같은 이름이어야 합니다.
4. **동기화**를 누릅니다. 아빠가 넣어 둔 근무 패턴과 일정이 엄마 휴대폰에도 나타납니다.

이후에는 일정을 추가하거나 근무를 바꾼 사람이 **동기화**를 누르면 다른 쪽도 동기화할 때 같은 내용을 받습니다. 근무 패턴은 마지막으로 저장한 쪽을 기준으로 맞춰집니다. 둘이 동시에 패턴을 고치지 않는 것이 좋습니다.

## 8. 동기화를 누르면 무슨 일이 일어나나

- 가족 이름, 색, 근무 종류, 패턴, 하루 변경은 캘린더 안 1999년 1월 1일 일정(**가족캘린더 설정 (지우지 마세요)**)에 보관됩니다. Google 캘린더 앱에서 그 일정이 보여도 지우지 마세요.
- 보통 일정은 제목, 시간, 메모, 누구의 일정인지가 그대로 오갑니다.
- 근무 일정은 제목 앞에 이름이 붙고(예: `아빠 주간`), 앱이 만든 일정이라고 표시됩니다. 패턴을 바꾼 뒤 동기화하면 **오늘 기준 약 한 달 전 ~ 4개월 뒤** 근무 일정만 다시 만들어집니다. 그 밖의 일반 일정은 건드리지 않습니다.
- 하루만 다르게 쉬거나 근무를 바꿀 때는 Google 캘린더 앱에서 근무 일정을 고치지 말고, 우리 앱의 **하루만 바꾸기**를 쓴 다음 동기화하세요. 그렇지 않으면 다음 동기화 때 패턴대로 다시 써집니다.

## 자주 막히는 곳

**“액세스 차단됨” 또는 테스트 사용자 오류**

엄마 또는 아빠 Gmail이 3단계 테스트 사용자에 없습니다. OAuth 동의 화면의 테스트 사용자에 그 메일을 추가하고 몇 분 뒤 다시 로그인합니다.

**원본이 허용되지 않음 (origin is not allowed / redirect_uri_mismatch)**

자바스크립트 원본이 `https://podolsch-lang.github.io` 와 글자 하나까지 같은지 봅니다. `http`, 경로, 다른 주소가 들어가면 실패합니다. 고친 뒤 5분 정도 기다리고 새로고침합니다.

설정 화면 아래에 `지금 주소:`가 나옵니다. 여기가 `https://podolsch-lang.github.io` 가 아니면, 그 주소의 **출처(scheme + 도메인 + 포트)** 를 원본에 추가해야 합니다. 컴퓨터에서 `http://localhost:8080` 으로 시험할 때만 그 주소를 원본에 추가로 넣으면 됩니다.

**팝업이 바로 닫힘**

브라우저가 팝업을 막은 경우입니다. 주소창의 팝업 차단을 허용하고 다시 누릅니다.

**엄마 목록에 가족 캘린더가 없음**

초대를 아직 수락하지 않았거나, 권한이 ‘모든 일정 세부정보 보기’만 있고 변경은 안 되는 상태일 수 있습니다. 공유 권한을 ‘일정 변경’으로 올립니다.

**동기화 후 근무가 Google 캘린더 앱에 안 보임**

우리 앱에서 패턴을 저장한 뒤 **동기화**를 눌렀는지 확인합니다. 표시 범위는 오늘 근처 몇 달입니다. Google 캘린더 앱에서 가족 공유 캘린더의 체크가 켜져 있는지도 봅니다.

**사이트가 예전 설정 그대로**

`config.js`를 저장한 브랜치가 `main`인지, Actions 배포가 끝났는지 확인합니다. 휴대폰에서는 페이지를 새로고침합니다.
